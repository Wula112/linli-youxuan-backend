# 秒杀接口 1,000 线程压测报告

测试时间：2026-11-07 19:06，东八区。接口：`POST /voucher-order/seckill/{id}`。

> **2026-11-08 复核说明：**此轮沿用同一 JMeter 后置脚本并启动了新的压测 JVM；1,000 个线程中有 749 个在首次样本后出现超过 500 ms 的请求间隔，首间隔中位数约为 1,755.5 ms。5 秒爬升和客户端冷启动都会影响整轮平均并发；报告中的吞吐和响应时间是该次实际样本，不能直接作为稳定 1,000 并发的容量。详见[复核报告](jmeter-littles-law-diagnosis-2026-11-08.md)。

## 测试条件

- JMeter 5.6.3：1,000 线程、5 秒爬升、计划运行 20 秒，闭环连续请求；记录到的活跃线程峰值为 1,000。活跃线程数不等于同一时刻正在进行的 HTTP 请求数。
- 每次请求使用不同的合成用户，共准备 250,000 个用户；测试券初始库存 250,000。另用独立测试券执行了 200 次预热请求，预热请求全部受理成功。
- 应用、MySQL、Redis、RocketMQ 与 JMeter 均位于同一台 Windows 主机，使用独立端口与全新测试数据库。应用采用 `sharding` 配置，订单消费线程为 4；本轮使用本地调度器，未测试 XXL-JOB Admin 调度。
- 根据前面的要求，仅在压测实例中关闭限流切面；正式源码中的限流逻辑未改动。熔断检查仍启用。
- 测试环境的 Redis 未开启持久化、MySQL 未开启 binlog、RocketMQ 异步刷盘，不能据此推算生产持久化条件下的性能。压测器与服务共用主机资源。

本次沿用上轮基于 `d0fea3d` 和当时未提交工作树构建的应用副本；压测前核查相关源码没有晚于该构建产物的修改。该副本仅通过专用启动器停用限流并将 Redisson 指向隔离 Redis。

## 接口结果

| 指标 | 结果 |
| --- | ---: |
| 统计窗口 | 19.991 秒 |
| 总请求数 | 54,921 |
| 业务受理成功 | 54,889（99.9417%） |
| 连接失败 | 32（0.0583%） |
| 总请求吞吐 | 2,747.29 次/秒 |
| 成功受理吞吐 | 2,745.69 次/秒 |
| 成功请求平均响应时间 | 292.04 ms |
| 成功请求 P50 / P90 | 294 / 362 ms |
| 成功请求 P95 / P99 | 372 / 385 ms |
| 成功请求最大响应时间 | 396 ms |

统计窗口是从第一条请求开始到最后一条请求结束；吞吐量按对应请求数除以该窗口计算。响应时间只统计成功受理的请求，分位数使用最近排名法。

32 次失败均为连接建立时遭拒绝，均发生在第一个请求开始后的 1 秒内，没有取得 HTTP 响应；具体原因尚未定位。请求返回的 HTTP 状态为 200 不足以判断业务成功，上述受理结果按响应 JSON 分类。

## 请求结束后的快照

按要求未等待消息全部处理。最后一个 HTTP 请求在 19:06:26.242 结束；约 2 秒后先读取 Redis，再读取数据库，两处并非同一时刻的原子快照。

| 指标 | 快照值 |
| --- | ---: |
| Redis 预占记录 | 54,889 |
| Redis 待处理记录 | 53,495 |
| Redis 剩余库存 | 195,111 |
| 数据库已创建订单 | 1,401 |
| 数据库剩余库存 | 248,599 |
| Redis 熔断标记 | 未观察到开启 |

Redis 数据在 19:06:28.294 左右取得，数据库查询在约 19:06:28.327～19:06:28.417 完成；期间消费者可能继续处理。因此不要直接用两次读取的数字做精确差值。Redis 待处理记录也不等同于 RocketMQ Broker 的精确消息积压量，可能包含正在处理或等待清理的订单。

快照后即停止隔离服务，**未等待 MQ 消费完成、未逐笔核对所有成功响应是否最终建单，也未验证最终库存一致性或最终无超卖**。这些未处理请求均为隔离环境中的合成测试数据。

## 资源观察

测试窗口附近的采样显示，整个主机平均 CPU 使用率约为 53.22%；应用进程平均约使用 7.10 个逻辑核、工作集峰值 982.4 MiB，JMeter 平均约使用 3.22 个逻辑核、工作集峰值 647.1 MiB。CPU 为采样区间平均值，工作集不等于 Java 堆；首尾采样可能稍超出请求窗口。

本轮的 2,745.69 次/秒是短时**接口受理吞吐**，不是订单落库吞吐或长期稳定容量。与上轮 200 线程测试的持续时间、样本规模、数据状态不同，不宜直接比较得出容量结论。

JMeter 明细、采样、快照和启动配置位于本机 `target/seckill-benchmark-1000t-20261107-190000` 目录。该目录属于构建输出，不提交到 Git，清理 `target` 时这些原始数据可能被删除。
