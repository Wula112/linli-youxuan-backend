# RocketMQ 秒杀异步下单

```text
秒杀请求 → 事务半消息 → Redis 预占并登记 pending / 订单请求索引
         → 返回订单号 → MQ 消费者、订单查询或 XXL 对账创建订单

消费失败 → RocketMQ 重试 → 死信消费者打开熔断并登记 DEAD_LETTER
         → XXL 对账继续建单，同时向 Admin 上报失败触发告警
```

接口返回订单号表示预占成功、订单已受理，不表示订单已落库。查询本人订单时若尚未建单，会利用 Redis 中的请求索引直接调用事务建单；异常时返回处理中，由对账继续尝试。三个建单入口通过同一条处理记录串行化，重复消息不会重复扣减数据库库存。

死信消费者独立订阅 `%DLQ%hmdp-voucher-order-consumer`，先打开持久化熔断，再登记处理记录，均成功才确认；登记失败或消息无法解析会返回失败。熔断期间拒绝新预占，已受理订单继续处理。配置 XXL Admin 的 SMTP 和任务告警收件人后，对账任务的失败上报触发邮件。

生产者采用事务半消息，Redis 本地事务标记与预占同脚本写入，Broker 可根据标记回查。入口无法确认结果时不会直接补偿：若确认本单已预占或已建单，返回订单号；否则返回结果待确认，pending 存在时仍由对账恢复。

订单主题也承载定时关单消息；启用 Broker 消息类型校验时应核对两种消息的主题兼容性。索引迁移、熔断恢复与验证见[订单对账说明](seckill-order-reconcile.md)，超时关单见[自动关单说明](voucher-order-timeout.md)。
